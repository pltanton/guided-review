# Change tree viewer — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The viewer shows the whole change as one diff with a file tree; the agent fills briefing, per-file order and why, flags and notes while the reviewer reads. Steps, chapters, the walk and carried steps go.

**Architecture:** `state.Review` loses `Steps/Carried/Current` and gains `Briefing`, `Hotspots`, `Annotations`, `File.Order/Why/Read/Seen`. `gr plan set` merges a partial plan. The viewer builds rows from `review.Files` in tree order (order, path; boilerplate and generated folded at the end). Coverage is `File.Seen`, written by the viewer, read by `gr prepare`/export and the next round. Inbox events and comments lose their step id.

**Tech stack:** Go 1.24, bubbletea, yaml.v3. Tests: `go test ./...`, e2e harness in `cmd/gr/e2e_test.go`, view fixture `newTestModel` in `internal/view/model_test.go`.

Spec: `docs/superpowers/specs/2026-11-04-change-tree-viewer-design.md`.

Deviations from the spec, decided here for less code:

- Keys stay: `]`/`[` hunks, `}`/`{` files (tree order = agent order), `n`/`N` any note (flag, thread, comment). No separate flag and thread jumps. No `B`: the briefing sits at the top, `gg` reaches it.
- Files the reviewer did not read in the previous round come back with the dot (unseen), not dim. Dim is only "agent has not read".
- `gr check [--undo] <n>` replaces `gr step check`; `n` is the 1-based index in `review.Hotspots`, the RISK number the viewer shows.
