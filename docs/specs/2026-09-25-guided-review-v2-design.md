# Guided review v2 — дизайн

Дата: 2026-09-25. Основа: `2026-09-25-guided-review-design.md`, фидбек первого прогона
(daedalus MR !69).

## Что меняется

1. Checkout без вопросов: отдельный worktree под ревью.
2. Вьювер — основной интерфейс: план, текущий шаг, сообщения агента и ввод в одном окне.
3. Канал вьювер → агент (`gr wait` / `gr say`).
4. Аннотации агента на строках кода; замечания и дискуссии MR там же.
5. Split view, мышь, «поясни этот кусок».
6. Повторное ревью после фиксов автора.
7. Дискуссии других ревьюеров из MR.
8. Скил: быстрый intake, без вопросов про ветку.

## 1. Worktree

- HEAD уже на head MR → работаем в рабочем дереве.
- Иначе `gr init` создаёт `git worktree add --detach` в
  `<UserCacheDir>/guided-review/<repo>-<id>` (или переводит существующий на новый head).
  Путь пишется в `state.worktree` и печатается `code: <path>`.
- Вьювер (`e`) и агент работают с этим путём. Рабочее дерево пользователя не трогается.
- `gr done` удаляет worktree и снимает текущее ревью; состояние остаётся для
  повторного ревью.
- Указатель текущего ревью — отдельный на каждое рабочее дерево
  (`current-<hash toplevel>`): ревью в разных worktree репозитория не мешают друг другу.
- `gr list` — ревью репозитория.

## 2–3. Единый интерфейс и канал

```
┌ plan ────────────┬ s3/12 entry · POST /transfers ──────────────────────┐
│ ✓ s1 contract    │ +  57 │  h.repo.Reserve(ctx, req.Amount)            │
│ ▶ s3 handler ⚑   │       ┆ ⚑ повтор с тем же key — второе списание?    │
│ · s4 logic       │ +  58 │  return h.outbox.Put(ctx, ev)               │
├──────────────────┴──────────────────────────────────────────────────────┤
│ claude: Валидирует, резервирует, пишет в outbox. Вопрос — ⚑57.          │
│ › _                                                                     │
└─────────────────────────────────────────────────────────────────────────┘
```

Инвариант: `state.yaml` пишет только `gr` (агент). Вьювер пишет только
`inbox.jsonl` и никогда не меняет состояние сам.

- Вьювер → агент: события в `<review>/inbox.jsonl`:
  `{id, time, kind: message|explain|next|skip|goto, text, file, lines, step}`.
- `gr wait [--timeout 9m]` блокируется до новых событий, печатает их и сдвигает
  курсор чтения (`inbox.offset`). Таймаут — не ошибка: печатает `no input yet`,
  агент вызывает снова.
- Агент → вьювер: `gr say TEXT` добавляет сообщение в `state.messages`
  (последние 50).
- Вьювер показывает переписку текущего шага: свои события из inbox и сообщения агента.

Клавиши:

| Клавиша              | Действие                                                     |
| -------------------- | ------------------------------------------------------------ |
| `j`/`k`, колесо      | движение                                                     |
| `]`/`[`              | hunk                                                         |
| `n`/`N`              | аннотация                                                    |
| `v`                  | выделение строк (или drag мышью)                             |
| `c` / `enter`        | написать агенту; выделение или строка курсора прикладываются |
| `?`                  | поясни выделение / строку                                    |
| `>`                  | следующий шаг (событие `next`)                               |
| `S`                  | пропустить шаг с причиной                                    |
| клик по шагу в плане | `goto`                                                       |
| `s`                  | split / unified                                              |
| `p`                  | показать / скрыть план                                       |
| `m`                  | захват мыши вкл/выкл                                         |
| `tab` / `shift+tab`  | контекст                                                     |
| `e`                  | `$EDITOR`                                                    |
| `q`                  | выход                                                        |

## 4. Аннотации

- Шаг получает `annotations: [{file, line, kind: note|spec, text}]` — в плане или
  по ходу `gr note add --file F --line N [--kind note|spec] TEXT`.
- Хотспот с `line` рисуется как аннотация `⚑`.
- Замечания ревьюера текущего раунда и дискуссии MR рисуются под своей строкой другим
  цветом.
- Вьювер показывает аннотацию виртуальной строкой под кодом.

## 5. Split view

Строки split выводятся из unified: подряд идущие удалённые и добавленные строки
hunk'а склеиваются попарно, неизменные строки одинаковы слева и справа, номер старой
строки считается через сдвиг предыдущих hunk'ов. Ширина меньше 120 колонок →
unified и подсказка.

## 6. Повторное ревью

`gr init <url>` для существующего ревью, когда head MR сменился:

- открывается раунд N+1; прошлый head запоминается;
- старый head — предок нового → дифф раунда `oldHead..newHead`;
- иначе (rebase) → дифф MR целиком, но в покрытие плана входят только файлы, чей патч
  изменился;
- шаги прошлого раунда заменяются новым планом, замечания остаются;
- открытые замечания прошлых раундов агент проверяет первым шагом:
  `gr comment resolve ID` / оставить открытым.

## 7. Дискуссии MR

- `gr init` и `gr sync` забирают `glab api --paginate
projects/:id/merge_requests/:iid/discussions`.
- В состоянии: автор, первый комментарий, число ответов, файл/строка (если есть),
  resolved.
- Позиционные показываются во вьювере на строке; общие — в выводе `gr init` /
  `gr status` для intake.

## 8. Скил

- Intake только по описанию MR, спеке, дискуссиям и `git diff --stat`, сразу
  «верно понял?»; код читается после подтверждения.
- Никаких вопросов про ветку: `gr init` сам делает worktree, агент читает код по пути
  `code:`.
- Шаг: `gr say` вместо чата, затем `gr wait`; события обрабатываются как реплики
  пользователя. Чат остаётся запасным каналом.
